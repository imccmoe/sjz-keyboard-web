feat(ui): 恢复悬停反馈、主题按钮改浮动、星球显示全部曲目

用户四项反馈中的三项：

1. 恢复按钮悬停反馈
   上一轮为绕开「悬停变白」直接删掉了悬停，用户要求加回来。
   这次用 :not(.primary) 让通用规则明确排除主按钮，
   主按钮自己的悬停态显式重声明紫色底与 --on-accent 文字色 ——
   不再依赖两条同优先级规则的书写顺序。

2. 主题切换按钮移到右下角浮动
   原先占顶部栏位置。改为静态 HTML 里的圆形浮动按钮（position: fixed），
   不再参与渲染函数重建（浮动元素被重建会闪动、丢焦点）。
   theme.js 新增 modeIcon()/modeName()，按钮只显示图标，说明放 title/aria。

3. 音乐星球显示全部曲目
   根因是固定 20 组坐标配 songs.slice(0, 20)，第 21 首之后不渲染。
   改为按曲目数动态计算行数（6~11 行），坐标仍用百分比，
   因此 25 首会排得更密但容器高度不变 —— 不会撑高去压住下方键位卡片。
   顺带修正搜索栏文案（原先写死「星球展示 20 / 25 首」）。

过程中修复自己引入的两个回归：
- 网格行用 grid-auto-rows: auto 时，.planet 的 height:100% 无法解析成确定值，
  padding 把容器撑到 539px，盖住了键位卡片 -> 给 .library-stage 指定 grid-template-rows
- 试图用 CSS 变量把内容高度传给容器，但变量用在定义它的同一元素上会自引用，
  导致 height:100% 失效 -> 改为不需要滚动，高度由坐标自适应

新增 scripts/ui-layout-check.mjs（npm run ui:layout，12 项）：
用 CDP 实测主题按钮位置、星球坐标分布、容器高度是否等于舞台高度、
星球是否压住键位卡片，以及强制 :hover 时按钮颜色是否稳定。
