feat(db): 曲库迁到 Cloudflare D1，新增读写 API 与网页管理端

用户反馈「不要用 json 来存数据啊，不好更新啊，我要用 cloudflare 的数据库」。
原先曲库是 public/data/music-catalog.json，改一首歌要改文件再重新部署。

数据库（migrations/0001_songs.sql）
- songs 表存曲目，score 原样保存、music_id 唯一且稳定（它已经写进用户键盘）
- song_counters 单行计数器：用独立计数器而不是 MAX(music_id)+1，
  避免删除曲目后编号被复用导致键盘里显示错歌

API（functions/api/）
- GET  /api/songs            列表：stage / q / sort / limit / offset
- GET  /api/songs/:id        支持主键、曲目编号或标题三种定位
- GET/POST /api/admin/songs  管理端列表 / 新增 / 批量导入（merge、replace）
- GET/PATCH/DELETE /api/admin/songs/:id
- 管理端用 Authorization: Bearer，令牌比较为常数时间实现；未配 ADMIN_TOKEN 时接口关闭

前端
- loadCatalog() 优先读 API，失败时自动回退到 JSON 快照（离线或纯静态服务器仍可用）
- 新增 public/manage.html：令牌、曲目增删改、JSON 文件导入

另修两处自己写错的地方：
- 严格记号正则把 8 首合法曲目的写法（4_ 延长、| 小节线、【1_】 跨八度、（#6） 黑键）
  误判为非法。改为「长度上限 + 字符白名单 + 至少一个音符」的结构化校验，
  并用真实曲库 25 首做了正反验证
- admin/songs 的导入路径少了一级，导致管理端全部 500

测试与工具
- tests/songs-api.test.js（11 项）：列表筛选与 LIKE 转义、三种定位、鉴权、
  编号分配与不复用、replace/merge、迁移与种子 SQL 在模拟 D1 上真跑一遍
- scripts/build-song-seed.mjs（npm run db:seed）：JSON -> SQL，保留 music_id
- scripts/check-inline-modules.mjs（npm run check:inline）：查 HTML 内联模块语法
- scripts/ui-manage-check.mjs（npm run ui:manage，8 项）
